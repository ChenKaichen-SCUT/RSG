## 基础设施修复：正式批次重新开始

在首批留出运行中发现原生重放进程在 0.2 秒内被 SIGKILL（退出码 137）。再次全路径审计发现，除了 RunTasks.py，CondTerm.py 自身的 453/525/610 行也调用按进程名清理。因此只隔离目录不够，原并发批次可能互相结束 mono/z3/c5，整个旧 primary 批次降级为 `unisolated_pilot`，不纳入正式分母或算法效果结论。旧路径字符串仍保留在原始记录内，归档目录位置作对应变更。

服务器实际支持 `unshare --pid --fork --mount-proc`。正式每次进程树均置于独立 PID 和 /proc 命名空间，保留官方清理函数原样；按原来的四工作进程、种子 888、相同预算重新运行 24 个 smoke 和 242 个 holdout。候选语言、排序、算法与资源预算完全未调参。此前已查看的留出初步结果不再称为完全未见数据，报告明确这是隔离修复后重新评价；冻结实现仍是 1fc101f。另仅修复 Python/源目录可移植路径，不改变算法。

隔离后 smoke 阶段另修复 B 的超时管理：每次 native 重放使用 20 秒总预算的剩余部分，避免最后一次重放又获得完整 20 秒；超时单列为 replay_timeout。其余 SMT 方法在候选边界检查软墙钟预算，每条 SMT 查询另有 2 秒超时，最终独立验证单独计费。这是预算执行修复，不改变候选或搜索排序。

## 真实接入开发

隔离后的 AlternDivWidening 正式输入确认 D_symbolic 严格超过 A，但 B 重复官方也能扩大。由此满足有条件端到端接入的前提。另建 `work/integrated`，未替换正式采集二进制；官方方法先运行，在线 Python 方法使用本轮真实输入/VC 搜索，只有完整验证且严格包含官方结果时才接纳，否则返回官方结果。

首次接入试跑暴露官方 Python 前端不接受 `!(w <= c)` 这种 Z3 输出拼写。保留失败记录 `e2e_pilot_development_v1`，之后以 AST 将否定比较等价翻转为 `w > c`，并用最多 2 秒的 SMT 冗余项删除压缩 DNF；序列化前后再检查等价。该转换不改变候选语言/搜索结果，全部额外开销计入完整进程时间和 RSG 集成耗时。修复后 AlternDivWidening 三配置均成功，最终条件在真实入口 w=5 下等价并匹配精确条件 -5<=t<=5。

并行配对试跑时，发现每次 trial 的目录标签误用了外层循环变量，导致同程序试跑共用一个标签（迹象是 trace 数超过 RSLearn 次数）。在正式重复测量前停止该试跑，保留为 `e2e_pilot_pre_parallel_fix` / `e2e_pilot_parallel_development.json`。修复为从当前 trial 读取 method，并增加已有工作目录/语料目录拒绝复用、trace 数和在线方法标签的一致性检查。正式 primary 语料未受此驱动程序错误影响，正式端到端数据在该修复之后开始。

单项析取的跨语言序列化还暴露了 `Or(one_term)` 被原生重放器误当一元负号的边界错误。试跑失败保留为 `e2e_pilot_unary_or_development`；编码器现把单元素 And/Or 编码为该元素，并显式处理空 And/Or、空种子。新增验证 C# **实际返回 AST** 与 Python 候选等价及完整 VC 有效性的独立检查，不能只验证 Python 一侧。

离线 Ex06 的有限闭包已证明 guard 是 11 个完整整数状态，并超过受限符号区域模板。正式集成的“简单闭包”采用通用 guard 有界性语法分派：每个整数变量在每个分支都有直接上下界时运行 D_finite（枚举完备仍由 SMT 证明），否则运行 D_symbolic。没有按程序名或已知目标集合分派。该集成选择在正式重复测量前固定，离线 A–E 的冻结算法、候选预算和结果不变。

最终集成试跑：通用有限 guard 分派在 Ex06 实际选择 D_finite，将 4 次外层迭代/3 次 RSLearn 降至 2 次/1 次；三个配置的最终条件与精确条件全部 SMT 等价。为适配官方 Python 前端，有限点的整数等式以两个不等式等价编码；编码前后及原生实际返回值均验证。最终条件中的 SymPy abs 使用独立 `condition_parser.py` 解析为整数 ITE，未更改离线候选/guard 解析器。Fibonacci 的符号闭包试跑减少一次迭代，但仍 Unknown；该慢失败程序保留进入正式 20 次配对测量。

## 双项枚举覆盖的事后修正版

审查冻结 E-v1 的预算分配发现：当每项有 16 个局部候选时，第一对项的 16×16 组合可用完 256 次预算，其他项对没有机会。保留原 `E_joint2` 结果和冻结源码，新增 `E_balanced`：候选池、模板、256 次/20 秒预算不变，仅按项对轮转。该修复明确发生在见过初步留出结果之后，因此 E-v2 是事后补充评价，不能声称未调参的留出证据。例 `2Nested_false-termination/call_008` 的访问项对数从 1 增至 36/36，但并非穷举每对的全部候选。所有非空有效自然输入重新执行 E-v2，并保存与全部其他集合的双向 SMT 包含比较。正式端到端 joint 使用 E-v2；正式计时尚未开始。
